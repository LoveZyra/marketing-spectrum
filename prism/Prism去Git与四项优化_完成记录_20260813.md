### 删掉的

后端 6 个文件:`routes/git.js`、`routes/git-args.js`、`utils/gitConfig.js`、
`routes/git.test.js`、`routes/tests/git-args.test.js`、

确认没问题后自己删那个目录即可。

### 改掉的

- `installMode` 固定 `'npm'`,不再探测 `.git`;
- **`POST /api/system/update` 整条路由摘掉** —— 它的放行条件是 `isPlatform || installMode === 'git'`,
  固定 npm 后永远返回 501,留着就是一个永远失败的接口。前端"立即更新"按钮同步去掉,
  升级指引统一成 tar 包文案(`tar -xzf ... && npm ci && npm run build`);
- 新建项目向导去掉 GitHub URL 与令牌卡片,只能指向服务器上已存在的目录;
- 首次引导从两步变一步 —— 原来第一步是配 git 身份,写的是 `git config --global`,
  接口没了这步也就没有意义;
- 设置页去掉 Git 页(git 身份配置)。**GitHub 令牌区保留** —— 它服务的是 `/api/agent`,不是界面里的版本控制。

### 三处清单外的判断

1. **`server/routes/agent.js` 的 GitHub 能力:先摘掉,后按要求恢复了。**
   这是 API-key 鉴权的外部接口 `/api/agent`,支持 `githubUrl` 克隆仓库、
   `createBranch`/`createPR` 建分支提 PR。第一版按"去除所有 git 功能"把它摘了,
   确认后**已完整还原**(`agent.js` 回到原始的 1215 行,`github-tokens.ts` 与
   `githubTokensDb` 导出一并恢复)。

   它取令牌的顺序是:请求体里的 `githubToken` → 库里 `user_credentials` 表
   `credential_type='github_token'` 的活跃行。设置页 API Tokens 里管理这些行的
   GitHub 令牌区**也一并恢复**了,所以令牌可以在页面上增删启停。

   **这是 Prism 里唯一还会执行 git 命令的用户功能** —— 部署的服务器上必须装 git,
   否则克隆和建分支会报 `Failed to execute git`。

2. **插件从 git 仓库安装保留了。** `utils/plugin-loader.js` 的 `installPluginFromGit`
   会 `git clone`。它是插件唯一的安装途径,删了插件系统就没法装东西;
   而且它是"安装机制",不是给用户用的版本控制功能。

3. **Agent 权限示例里的 `Bash(git log:*)` 没动。** 那是给 Claude 用的工具权限白名单示例,
   不是 Prism 的 git 功能 —— 删了等于限制 agent 能被授予什么权限。

### 没动的

检查点(Checkpoints)完全没动,代码、开关、前端入口全在。
`users.git_name`/`git_email` 两列与 `github_tokens` 表**只停止读写,没删**
(SQLite 老版本不支持 DROP COLUMN,删列要重建表,风险大于收益)。

## 二、四项优化(已完成)

### 批次 1 · 账号隔离与注册审批

| 项 | 实现 |
|---|---|
| root 认定 | `PRISM_ROOT_USERS=tianji.chang`(逗号分隔),**不落库**,每次请求现算 |
| 注册 | 新账号 `pending`,不发 token;首个账号与 root 用户名直接 `approved` |
| 登录 | 顺序:密码 → root 放行 → `PRISM_APPROVAL_REQUIRED=0` 跳过 → 查状态。待审/驳回文案不同 |
| 审批接口 | `GET /api/admin/users`、`POST /api/admin/users/:id/{approve,reject}`,全部走 `requireRoot`,写 audit_log |
| 项目可见性 | 非 root 只看 `owner_user_id = 我 OR IS NULL`;root 看全部 |
| 归属变更 | `PATCH /api/projects/:projectId/owner`,`{ ownerUserId: number \| null }`,root 限定 |
| 存量项目 | 启动时一次性归 root,标记写 `app_config.projects_owner_backfilled`;root 账号不存在就跳过、下次启动再试 |

**注册入口是新加的** —— 原来 `/auth/register` 在有用户后一律 403(单用户系统),
登录页也没有注册链接。现在登录页有"申请账号",提交后显示"等待审批"的整页状态
(不是 toast:否则人转头就去登录,撞上 403 且没有解释)。

三道防锁死保险都在:列默认 `'approved'`(存量账号不受影响)、root 绕过审批、
`PRISM_APPROVAL_REQUIRED=0` 一键关闸。

**这是界面隔离,不是越权防护。** 各 project 级接口(files/checkpoints/taskmaster…)
没加归属校验 —— 知道 projectId 的人照样能调。这是清单里刻意的取舍,
已经写进设置页的说明文字里,别让人误以为已经隔离了。

### 批次 2 · 执行模式挡位

原来输入区那个按钮是**盲循环**:点一下换一挡,五挡只靠颜色和两个词区分,
其中 `bypassPermissions`(全放行)和 `acceptEdits`(改文件不问)是真的会交出权限的。
现在改成显式下拉,按权限从小到大排,每挡一行说明,危险的那挡永远在最后。

挡位值与服务端原有的 permission mode 一一对应,**没有新增接口**,
逐次确认仍然保留作为兜底。按会话记忆(原本就有),Tab 仍可循环。

### 批次 3 · 静态网页发布

一张表 + 一个公开路由。右键文件/目录 → "生成分享链接",拿到 `/p/<token>/`,
复制即分享,无需登录。**只存路径不拷文件**:改完文件刷新就生效,删记录即失效。

安全上:公开路由挂在 `/api` 闸门之前、用 `/p` 独立前缀(以后给 `/api` 加中间件不会连坐)、
自带限流、路径走现有的 `validatePathInProject`(词法 + realpath 双重校验)、
MIME 白名单(白名单外一律 `attachment` 下载)、`nosniff` + CSP。

**顺带解决了报告外链锚点的问题**:返回 HTML 时注入 `<base href="/p/<token>/">`,
锚点解析锁死在自己的地址上,嵌到别人页面里点"目标人群"不会再跳到服务器页。
注入位置是 `<head>` 之后**第一个**元素 —— 插在后面对已声明的资源不生效;
页面自己写了 `<base>` 就不动它。

### 批次 4 · HTML/Markdown 双模预览

HTML 预览原来是"新开窗口 + `srcdoc`"。`srcdoc` 文档**没有 base URL**,
页面里的 `<link href="style.css">`、`<img src="./chart.png">` 一律加载不到 ——
凡是样式和图表分离的报告,预览出来就是一堆没样式的文字。

现在改成编辑器内的 iframe,`src` 指向 `/preview/<ticket>/<文件名>` 真实 URL,
相对资源正常解析。票据 5 分钟过期、限定在文件所在目录、可重复使用
(一次预览要拉文档加它引用的全部资源)。

iframe **不给** `allow-same-origin` —— 它与 `allow-scripts` 同给等于没有沙箱,
被预览的页面能拿到 Prism 的 localStorage 和登录令牌。

一个行为变化:预览读的是**磁盘上已保存的文件**,不是编辑器缓冲区。
有未保存改动时预览顶部会出现提示条 + 重新加载按钮 —— 不提示的话
"我改了但预览没变"会比现在更难查。

## 五、模型切换(2026-08-13 追加)

### 症状

`/models` 里选了模型,弹窗提示"下一轮生效",再打开 `/models` 当前模型又变回 `default`,
看起来像切换没生效。

### 根因(两个,叠在一起)

**① `/models` 报告的当前模型永远是 `default`。** 输入框执行命令时发的是 Prism 的
**app session id**;`getCurrentActiveModel` 拿它去读会话的 `jsonl_path` —— 那是 **Claude 自己的
对话记录** —— 而记录里每条事件带的都是 **Claude 的 session id**。
`extractClaudeEventModel` 里那句 `if (eventSessionId !== sessionId) return null` 于是把每一行都挡掉,
读不出任何模型,回落到 `CLAUDE_FALLBACK_MODELS.DEFAULT`,也就是字符串 `'default'`。

有个让人误判的地方:**磁盘扫出来的历史会话**两个 id 是同一个,显示正常;
只有**在 Prism 里新建的会话**才坏 —— 也就是绝大多数。这让问题看起来时灵时不灵。

**② 两个模型控件互相看不见。** 新建对话页的下拉框写的是客户端默认值(localStorage),
`/models` 写的是会话级覆盖文件;而 `resolveResumeModel` 里覆盖优先级更高。
所以一个会话被 `/models` 切过之后,下拉框对它就彻底失效了 —— 选 Haiku,每轮还是跑 Opus,没有任何提示。

### 改法

- **删掉新建对话页的模型下拉框**,那张卡片改成只读展示 + 一行"输入 /models 切换模型"。
  模型切换从此只有一个入口。
- `/models` 选完之后**同时**写会话覆盖和客户端默认值 —— 否则下拉框没了,
  默认值就再也改不了,新对话永远停在几个月前那个模型上。
- 读对话记录前先把 app session id 换成 `provider_session_id`(取不到就回退用原值,
  磁盘会话不受影响)。
- `getCurrentActiveModel` 先看一眼待生效的覆盖:刚切完还没发下一轮时,
  报**将要生效**的模型而不是记录里的旧模型,否则又是"看起来没切成功"。

### 用户能不能感知到切换

改之前:整个对话过程中界面上**没有任何地方**显示当前模型 —— 唯一显示模型的是新建对话页那张卡片,
一旦开始对话就看不见了。所以切完只能凭那句"下一轮生效"的提示相信它,关掉弹窗就再也无从确认。

现在两处都能看到:

- **`/models` 弹窗内**:顶部"Active model"显示当前模型(以前这里永远是 `default`),
  切完立刻变成 `→ opus next`,被选中的卡片打上"Applies next response",底部一行说明下一轮用哪个;
- **输入框工具栏**:新增一个只读的模型标识(CPU 图标 + 模型名),鼠标悬停提示"输入 /models 切换"。
  它读的是**服务端认定的当前会话模型**(新增 `GET /api/providers/:provider/sessions/:id/active-model`),
  不是前端那个默认值 —— 所以它显示什么,下一轮就跑什么。切换后立即刷新,切会话时跟着重新拉。

### 验证

`server/modules/providers/tests/claude-active-model.test.ts` 四个用例。
把两处修复分别改回去跑过,对应的用例确实会红 —— 不是那种改不改都绿的摆设测试。

**没有验证到的**:切换动作本身是否真的作用到下一轮。三条发送路径(常驻 / 单次 / `/loop`)
都在建 runtime 之前调了 `resolveResumeModel`,常驻那条还会调 SDK 的 `query.setModel`,
代码上是通的,但没有真跑一个 Claude 会话观察到。部署后建议实测一次:
切到 haiku,发一轮,看回复里的模型标识。
