# Prism 新服务器部署说明

本包是 **Prism 源码**(不含 `node_modules` / `dist` / `dist-server` / `.git` / `.env`),
在目标机现装依赖、现构建。原生模块(better-sqlite3 等)必须在目标机编译,
所以不能把老机器的 `node_modules` 拷过来。

## 已包含的自定义改动

这份源码不是上游原版,含本团队的补丁,升级 Prism 时要留意:

| 改动 | 文件 | 说明 |
|---|---|---|
| **上传分片化** | `server/routes/documents.js`、`src/components/chat/hooks/useChatComposerState.ts`、`server/modules/files/files.routes.ts`、`src/components/file-tree/hooks/useFileTreeUpload.ts` | 绕开反向代理的 `client_max_body_size`。超过一片的文件切片逐个上传,服务端按序追加还原;小于一片的走原路径不变。分片默认 15MB,`PRISM_LAND_CHUNK_MB`(聊天附件)与 `PRISM_UPLOAD_CHUNK_MB`(Files 面板)可调 |

## 部署步骤

```bash
tar xzf prism-full-<日期>.tar.gz -C ~/          # 解出 ~/prism
cd ~/prism
bash deploy.sh                                   # 体检 → npm ci → 生成 .env → 构建
# 按提示改完 .env 后
npm run server
```

`deploy.sh` 不会自动起服务——端口、反代、密钥这些得你确认过再启。

### 前置条件

Node **>= 22**(`.nvmrc` 写的是 v22,`package.json` 的 engines 也卡了这个);npm;
能访问 npm 仓库;原生模块编译需要 python3 + make/build-essential(缺了会在 `npm ci`
阶段报 node-gyp 错误)。

### .env 必须过一遍的几项

- `SERVER_PORT` 后端端口(默认 8080)。走网关反代时与反代目标保持一致。
- `HOST` 监听地址。前面有反代就设 `127.0.0.1`,别 `0.0.0.0` 裸奔——任何能连到这个
  端口的人都可以尝试登录,登录后就能驱动 agent 执行命令。
- `JWT_SECRET` 不设会自动生成并存进库;要可迁移或多实例就显式设一个长随机串。
- 若同机还要跑营销诊断服务:`PRISM_MA_API_TARGET`(必须回环地址)、
  `PRISM_MA_API_AUTOSTART`(绝对路径,让 Prism 顺带拉起上游并在退出时收掉)、
  `PRISM_MA_API_PYTHON`。
- `PRISM_ALLOW_QUERY_TOKEN=1` —— 浏览器发起 WebSocket 时设不了 Authorization 头,
  只能用 `?token=`;服务端默认不读 query token,**不开这一项对话和 shell 会全挂**。

## 反向代理

网关/nginx 三件套,少配一件大文件上传就会 413 或 504:

```nginx
client_max_body_size 512m;    # 与 Prism /land 的 500MB 上限对齐;Files 面板要到 2048m
proxy_request_buffering off;  # 大文件不在网关落盘缓冲,直接流给上游
proxy_read_timeout 1800s;     # 与 Prism 的 30 分钟 requestTimeout 对齐
proxy_send_timeout 1800s;
```

即使不配,上传分片补丁也能让文件传上去(每片都小于代理上限),但其它大请求仍会撞墙,
建议一并配好。新环境先测一下代理的实际上限,若低于 15MB,把两个 `*_CHUNK_MB` 调到它之下。

## 数据与状态

`~/.prism/` 存 auth.db(账号、令牌)和上传的图片资源,首次启动自动创建。
换机器要保留账号就整体拷这个目录;想干净起步就别拷,页面上重新注册即可。

上传的附件落在 `~/html-server/staging/`(不对外提供访问),会一直堆着不自动清理,
定期看一眼占用。

## 不在本包内、但可能需要的东西

- **`restart_prism.sh`** —— 重启入口脚本,随营销诊断的 `ma-fix` 包发布,装在 Prism
  根目录。只装 Prism 的话用 `npm run server` 或自己接 pm2/systemd 即可。
- **营销诊断服务(ma-api-mode)** —— 独立的 Python 服务,自带 `install.sh`,与 Prism
  分开部署;Prism 侧通过 `/api/ma/*` 反代到它。
- **claude CLI 与 skills** —— agent 能力依赖它们,按各自的方式安装。

## 冒烟验证顺序

1. `curl -s localhost:<端口>/health`
2. 浏览器打开 → 注册/登录 → 新建项目 → 发一条消息(验证 WebSocket 通)
3. 上传:先传 **<15MB** 的文件(走原路径,确认基础没坏),再传 **~20MB** 的
   (走分片,F12 Network 里应看到多个 `chunk` 请求)
4. 聊天附件与 Files 面板是两条独立链路,各测一遍

> 分片上传的两条链路里,`/api/documents/land` 那条跑过真实端到端测试(54.4MB 切片后
> md5 与原文件逐字节一致等 15 项);**Files 面板那条只做过语法检查**,新环境务必按
> 上面第 3、4 步认真验一次,重点确认文件落在选中的目录里而不是项目根。
