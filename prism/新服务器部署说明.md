# Prism 新服务器部署说明

发布包是 Prism 源码(不含 `node_modules` / `dist` / `dist-server` / `.git` / `.env`),在目标机上安装依赖、现场构建。原生模块(better-sqlite3、node-pty)必须在目标机编译,不能把别的机器上的 `node_modules` 拷过来。

## 前置条件

- Node.js **>= 22**(`.nvmrc` 与 `package.json` 的 engines 都卡在这里)和 npm,能访问 npm 仓库;
- 编译原生模块的工具链:python3、make、g++(Debian / Ubuntu 装 `build-essential`),缺了会在安装依赖时报 node-gyp 错误;
- git:git 仓库里的每轮存档与回滚、外部 API 的克隆仓库 / 提 PR 都要用。

Claude Code CLI 随依赖一起装好(SDK 自带对应平台的二进制),不需要另装。

## 部署步骤

```bash
tar xzf prism-<日期>-v<版本>.tar.gz -C ~/     # 解出 ~/prism
cd ~/prism
bash deploy.sh                                # 体检 → 安装依赖 → 生成 .env → 构建
# 按提示改完 .env 之后
bash prism.sh start
```

`deploy.sh` 不会自动启动服务:端口、反向代理、密钥要先确认。之后的日常操作都用 `prism.sh`:

```bash
bash prism.sh restart     # 改完 .env 或升级之后
bash prism.sh status      # 进程、端口、健康检查
bash prism.sh logs        # 跟日志
bash prism.sh stop
```

升级时解包会覆盖同名文件,但不会删掉新版本里已经不存在的文件。构建前的自检(`scripts/check-retired-files.mjs`)会拦下会干扰构建的残留文件,并给出要删的路径。

## Claude 的配置:`~/.claude/settings.json`

对话、终端、定时任务里的 Claude 都读这份文件。至少要有:

- 网关地址与令牌(`env.ANTHROPIC_BASE_URL`、`env.ANTHROPIC_AUTH_TOKEN`)和模型映射;直连官方 API 时也可以在 `.env` 里设 `ANTHROPIC_API_KEY`;
- `cleanupPeriodDays`(建议 3650,不设时 CLI 30 天后清掉 transcript,老会话就续不上了);
- `crossSessionInbound: "refuse"`,以及 `permissions.deny` 里的 `SendMessage`、`ListAgents`。

这份文件必须是合法 JSON(不能带 `//` 注释,否则 CLI 整份忽略它)。Prism 启动时会检查它,日志里 `[claude 设置自检]` 开头的几行会逐项说明缺什么。

更多网关与个人 key 可以在「设置 → 模型网关」里配置,默认网关就是这份文件里的那一个。

## `.env` 必须过一遍的几项

- `SERVER_PORT`:后端端口(默认 8080),走反向代理时与代理目标一致。
- `HOST`:监听地址。前面有反向代理就设 `127.0.0.1`,不要直接 `0.0.0.0` 暴露:任何能连到这个端口的人都可以尝试登录,登录后就能驱动 agent 执行命令。
- `PRISM_TRUST_PROXY=1`:只在自己控制的反向代理后面时设,否则限流器把所有人算成一个 IP。
- `PRISM_ROOT_USERS`:管理员用户名,逗号分隔。它不会凭空建账号,要先用这个用户名注册,该账号才拿到 root;清空就没有人是 root,新注册的人会一直卡在待审批。
- `PRISM_PUBLIC_WORKSPACE`:公共工作目录,其下的项目对所有登录用户可见;不配则没有公共项目。
- `JWT_SECRET`、`PRISM_ENCRYPTION_KEY`:不设会自动生成并存进数据库;要能迁移到别的机器、或从备份恢复到别的机器,就显式设长随机串。

同机还要接营销诊断服务或推荐效果页时,再配 `PRISM_MA_API_*`、`PRISM_RECSYS_*`(见 `.env.example` 里对应的段落)。

## 反向代理

网关 / nginx 这三项少配一项,大文件上传就会 413 或 504:

```nginx
client_max_body_size 512m;    # 与聊天附件 500MB 的上限对齐;Files 面板要到 2048m
proxy_request_buffering off;  # 大文件不在代理上落盘缓冲,直接转给 Prism
proxy_read_timeout 1800s;     # 与 Prism 的 30 分钟请求超时对齐
proxy_send_timeout 1800s;
```

大文件按 15MB 分片上传,所以就算代理上限偏低,文件也传得上去;但其他大请求仍会被挡,建议一并配好。代理的实际上限低于 15MB 时,把 `PRISM_LAND_CHUNK_MB`(聊天附件)和 `PRISM_UPLOAD_CHUNK_MB`(Files 面板)调到它之下。

把 Prism 挂在子路径下(如 `/ai`)时用 `docs/nginx-subpath-template.conf`。模板里 `location ^~ /ai/` 有一句 `proxy_set_header Accept-Encoding ""`,是为了让 `sub_filter` 能改写响应里的 URL;它同时让 Prism 自己的压缩失效,所以模板在 nginx 侧另开了 `gzip on`,不要删。

## 数据与状态

- `~/.prism/`(`PRISM_DATA_DIR`):数据库 `auth.db`、数据库备份 `backups/`、git 存档 `checkpoints/`、最近删除的会话 `trash/` 等,首次启动自动创建。换机器要保留账号与会话记录就整体拷这个目录,同时拷 `~/.claude/projects/`(会话 transcript)。
- `~/html-server/staging/`:聊天附件落在这里(不对外提供访问),不会自动清理,定期看一眼占用。

## 冒烟验证

1. `bash prism.sh status`,健康检查那一行有内容就算起来了(`HOST` 绑了具体网卡地址时,`curl localhost` 连不上,`status` 会按 `.env` 里的 `HOST` 去查)。
2. 浏览器打开 → 注册 / 登录 → 新建项目 → 发一条消息,确认能收到回复。
3. 用 root 账号登录,「设置 → 关于」里能看到版本号、发布日期和提交号;有人待审批时,侧栏「设置」旁会出现红色数字。
4. 上传:先传一个小于 15MB 的文件,再传一个约 20MB 的(会分片,浏览器开发者工具的 Network 里能看到多个 chunk 请求)。聊天附件与 Files 面板是两条独立的链路,各测一遍,并确认文件落在选中的目录里。
5. 终端里点「接管会话」应进入 `claude --resume`;断开后回到聊天应能立刻继续对话。
6. 界面默认是中文;切到英文再刷新,应停在英文。
