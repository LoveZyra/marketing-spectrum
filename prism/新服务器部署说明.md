# Prism 新服务器部署说明

本包是 **Prism 源码**(不含 `node_modules` / `dist` / `dist-server` / `.git` / `.env`),
在目标机现装依赖、现构建。原生模块(better-sqlite3 等)必须在目标机编译,
所以不能把老机器的 `node_modules` 拷过来。

## 已包含的自定义改动

这份源码不是上游原版,含本团队的补丁,升级 Prism 时要留意:

| 改动 | 文件 | 说明 |
|---|---|---|
| **上传分片化** | `server/routes/documents.js`、`src/components/chat/hooks/useChatComposerState.ts`、`server/modules/files/files.routes.ts`、`src/components/file-tree/hooks/useFileTreeUpload.ts` | 绕开反向代理的 `client_max_body_size`。超过一片的文件切片逐个上传,服务端按序追加还原;小于一片的走原路径不变。分片默认 15MB,`PRISM_LAND_CHUNK_MB`(聊天附件)与 `PRISM_UPLOAD_CHUNK_MB`(Files 面板)可调 |
| **去 Git 功能** | `routes/git.js` 等 6 个后端文件、`src/components/git-panel/` 整目录 | 界面里的版本控制整体移除;`installMode` 固定 `npm`,`POST /api/system/update` 摘掉。**`/api/agent` 的 GitHub 能力保留**(克隆仓库、建分支提 PR),所以服务器上仍需装 `git` |
| **账号隔离与注册审批** | `server/shared/project-visibility.js`、`server/modules/database/session-visibility.ts`、`server/middleware/` | 项目/会话按 owner 可见(`owner_user_id = NULL` 表示公开,是有意设计);新注册账号默认待审批。root 由 `PRISM_ROOT_USERS` 每次现算,不写库 —— 换管理员改 .env 重启即可 |
| **默认语言中文** | `src/i18n/config.js` | `DEFAULT_LANGUAGE = 'zh-CN'`,英文降为按键兜底。用 `userLanguageChoice` 记录人工选择,与 i18next 自己的 `userLanguage` 缓存区分开 —— 否则老浏览器会被钉死在英文 |
| **移除四个功能** | 语音 / 任务(TaskMaster) / 浏览器(browser-use) / 插件 | 前后端整体删除,不是隐藏入口。**升级时注意:tar 只覆盖不删除**,残留的 `server/modules/browser-use/*.ts` 会让 `tsc` 编译失败 |
| **性能与隔离批次** | `server/index.js`(compression)、`src/stores/useSessionStore.ts`、`server/shared/ticket-store.js` | HTTP 压缩;每轮对话不再全量拉整份 transcript(3000 轮会话响应体 42 MB → 几百 KB);ws 票据与预览票据合并为一份实现(**预览票据可重复使用,不是一次性**,改动时别想当然) |
| **待审批红点** | `src/hooks/usePendingApprovalCount.ts` | root 登录后侧栏「设置」右侧显示待审批账号数,60 秒轮询 + 窗口聚焦时刷新 |

## 部署步骤

```bash
tar xzf prism-full-<日期>.tar.gz -C ~/          # 解出 ~/prism
cd ~/prism
bash deploy.sh                                   # 体检 → npm ci → 生成 .env → 构建
# 按提示改完 .env 后
npm run server
```

`deploy.sh` 不会自动起服务——端口、反代、密钥这些得你确认过再启。

### 前置条件

Node **>= 22**(`.nvmrc` 写的是 v22,`package.json` 的 engines 也卡了这个);npm;
能访问 npm 仓库;原生模块编译需要 python3 + make/build-essential(缺了会在 `npm ci`
阶段报 node-gyp 错误)。

### .env 必须过一遍的几项

- `SERVER_PORT` 后端端口(默认 8080)。走网关反代时与反代目标保持一致。
- `HOST` 监听地址。前面有反代就设 `127.0.0.1`,别 `0.0.0.0` 裸奔——任何能连到这个
  端口的人都可以尝试登录,登录后就能驱动 agent 执行命令。
- `JWT_SECRET` 不设会自动生成并存进库;要可迁移或多实例就显式设一个长随机串。
- 若同机还要跑营销诊断服务:`PRISM_MA_API_TARGET`(必须回环地址)、
  `PRISM_MA_API_AUTOSTART`(绝对路径,让 Prism 顺带拉起上游并在退出时收掉)、
  `PRISM_MA_API_PYTHON`。
- ~~`PRISM_ALLOW_QUERY_TOKEN=1`~~ —— **这条已经作废,不要再开。** 那是 ws 票据机制
  上线之前的口径。现在浏览器发起 WebSocket 走 `POST /api/auth/ws-ticket` 签发的
  一次性票据,对话和 shell 都正常;`?token=` 退化成需要显式打开的遗留兼容项,
  而查询串会进代理日志和浏览器历史、里面是完整 JWT。
  **从老机器 `cp` 过来的 `.env` 里如果还留着这一行,注释掉。**

> `.env.example` 里现在完整列着上传分片(`PRISM_*_CHUNK_MB`)和营销诊断服务
> (`PRISM_MA_API_*`)这两组变量 —— 以前只有本文档写着,新环境部署时看不到。

## 反向代理

网关/nginx 三件套,少配一件大文件上传就会 413 或 504:

```nginx
client_max_body_size 512m;    # 与 Prism /land 的 500MB 上限对齐;Files 面板要到 2048m
proxy_request_buffering off;  # 大文件不在网关落盘缓冲,直接流给上游
proxy_read_timeout 1800s;     # 与 Prism 的 30 分钟 requestTimeout 对齐
proxy_send_timeout 1800s;
```

即使不配,上传分片补丁也能让文件传上去(每片都小于代理上限),但其它大请求仍会撞墙,
建议一并配好。新环境先测一下代理的实际上限,若低于 15MB,把两个 `*_CHUNK_MB` 调到它之下。

**如果你用的是 `docs/nginx-subpath-template.conf`(把 Prism 挂在 `/ai` 之类的子路径下),
注意里面 `location ^~ /ai/` 有一句 `proxy_set_header Accept-Encoding ""`** —— 它是为了让
`sub_filter` 能改写响应体里的 URL 才关掉上游 gzip 的,副作用是把 Prism 自己的
`compression()` 一并废掉。模板里已经补了 `gzip on` 在 nginx 侧压回来,别删。
(`location ^~ /api/` 没有这句,所以大会话响应仍然是 Prism 压好的。)

## 数据与状态

`~/.prism/` 存 auth.db(账号、令牌)和上传的图片资源,首次启动自动创建。
换机器要保留账号就整体拷这个目录;想干净起步就别拷,页面上重新注册即可。

上传的附件落在 `~/html-server/staging/`(不对外提供访问),会一直堆着不自动清理,
定期看一眼占用。

## 不在本包内、但可能需要的东西

- **`restart_prism.sh`** —— 重启入口脚本,随营销诊断的 `ma-fix` 包发布,装在 Prism
  根目录。只装 Prism 的话用 `npm run server` 或自己接 pm2/systemd 即可。
- **营销诊断服务(ma-api-mode)** —— 独立的 Python 服务,自带 `install.sh`,与 Prism
  分开部署;Prism 侧通过 `/api/ma/*` 反代到它。
- **claude CLI 与 skills** —— agent 能力依赖它们,按各自的方式安装。

## 冒烟验证顺序

1. `curl -s localhost:<端口>/health`
2. 浏览器打开 → 注册/登录 → 新建项目 → 发一条消息(验证 WebSocket 通)
3. 上传:先传 **<15MB** 的文件(走原路径,确认基础没坏),再传 **~20MB** 的
   (走分片,F12 Network 里应看到多个 `chunk` 请求)
4. 聊天附件与 Files 面板是两条独立链路,各测一遍
5. **发布一个文件夹,打开分享链接,确认页面样式和图片都正常** —— 预览票据
   是可重复使用的,一次预览要加载文档本身加上它引用的每个资源;如果票据
   实现被误改成一次性,症状是第一张图之后全部 401
6. 设置页应当只剩:智能体 / 外观 / API 和令牌 / 通知 / 账号 / 关于;
   主内容区标签只剩:聊天 / 终端 / 文件
7. root 账号登录,有人待审批时侧栏「设置」右侧应出现红色数字,批准/拒绝后归零
8. 终端里点「接管会话」应当真的进入 `claude --resume`;点断开后回 chat 应当能立刻继续对话
9. 界面默认应当是中文;切到英文再刷新,应当**停在英文**(选择被记住)

> 分片上传的两条链路里,`/api/documents/land` 那条跑过真实端到端测试(54.4MB 切片后
> md5 与原文件逐字节一致等 15 项);**Files 面板那条只做过语法检查**,新环境务必按
> 上面第 3、4 步认真验一次,重点确认文件落在选中的目录里而不是项目根。
