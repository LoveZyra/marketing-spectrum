# Prism 四项优化 · 总体方案

> 2026-08-12。四项一起排期:账号隔离与审批、静态网页发布、执行模式挡位、HTML/Markdown 双模预览。
> 账号那一项的细则见《Prism账号隔离与注册审批_实施规格_20260812.md》,本文只写**四项之间的关系与顺序**,不重复。

## 为什么要放在一起看

三个交叉点,分开做会返工:

**① 三套 token 必须分开,不能复用。** 这是最容易出错的地方,先写死:

| 用途 | 生命周期 | 存储 | 可撤销 | 说明 |
|---|---|---|---|---|
| 发布 token | 长期 | 存库 `published_pages.token` | 是(删行即失效) | 对外分享用 |
| 预览 token | 5 分钟 | 不存库(签进 JWT) | 否(到期即死) | 编辑器里看效果用 |
| WS `?token=` | 会话级 | 现有机制 | 现有机制 | `PRISM_ALLOW_QUERY_TOKEN` 那套,不动 |

合并任何两个都会出问题:预览复用发布 token → 预览一次就产生一条可长期访问的记录;发布复用预览 token → 分享链接五分钟就失效。

**② 发布权限依赖项目归属。** 谁能发布/取消发布一个项目里的文件,取决于他是不是这个项目的 owner(或 root)。所以**账号隔离要先落地**,否则发布功能上线时权限模型是空的,后面还得回头改。

**③ 执行模式挡位与现有权限体系是两层,不是替代。** Prism 已有 `chatPermissions.ts` + `PermissionRequestsBanner`(agent 要动手时逐次确认)。挡位是**预设**——"这一轮我只要规划"、"这一轮放手改"。挡位决定默认给什么权限,逐次确认仍然保留作为兜底。别把逐次确认删掉换成挡位。

## 执行顺序

| 批次 | 内容 | 工作量 | 为什么排这儿 |
|---|---|---|---|
| 1 | **账号隔离后端** + 逃生开关(闸门默认关) | 1 天 | 权限模型是后面所有东西的地基;先证明零破坏 |
| 2 | **执行模式挡位** | 0.5 天 | 最便宜、纯前端、与其它三项零耦合;拿它把新服务器的构建/部署闭环跑通一次 |
| 3 | **静态网页发布** | 1 天 | 依赖批次 1 的归属;收益最大 |
| 4 | **双模预览** | 1–1.5 天 | 与发布共用文件读取路径,放在发布之后能复用一部分 |
| 5 | 账号隔离前端(审批面板 + 归属标记)+ 打开审批闸门 | 0.5 天 | 后端稳定后再开闸,避免边改边锁人 |

合计约 **4.5–5 天**。批次之间都能独立上线回滚。

## 各项要点(细则见各自文档)

### 批次 2:执行模式挡位

输入区加一个挡位选择器,四挡:

- **Auto** — 默认,现状行为
- **Plan** — 只规划不动手(映射到 Claude 的 plan 模式)
- **Manual** — 每个工具调用都要确认
- **Edit automatically** — 文件编辑自动放行,Bash 仍需确认

实现上是把挡位翻译成 spawn Claude 时的权限参数 + 前端的确认策略。**不新增后端接口**,挡位随消息一起发。落点:`ChatComposer.tsx`(选择器)、`useChatComposerState.ts`(带上挡位)、`chatPermissions.ts`(挡位 → 权限策略映射)。

挡位要**按会话记忆**(存 localStorage 或 session 表),不然每次新对话都要重选,很烦。

### 批次 3:静态网页发布

表结构、接口、公开路由挂载位置、文件夹整站的尾斜杠处理,见《Prism功能增强方案_20260812.md》A 节。补两条与账号隔离的衔接:

- `published_pages` 不单独存 owner,通过 `project_id → projects.owner_user_id` 推导;
- 取消发布权限 = 项目 owner 或 root;公共项目(owner 为空)的发布物,谁都能取消——这是"公共"的应有之义,但要在 UI 上给二次确认。

**顺带解决**:公开路由返回 HTML 时注入 `<base href="/p/:token/">`,你们那个"报告转外链后锚点跳到服务器页"的问题一并消掉。

### 批次 4:双模预览

Markdown 复用聊天区现成的 `Markdown.tsx`(react-markdown + remark-gfm + rehype-highlight),零新依赖。HTML 走 `<iframe sandbox="allow-scripts">`(**不给** `allow-same-origin`,两者同给等于没沙箱)+ 5 分钟预览 token 的资源路由 + `<base>` 注入。

## 统一约束

1. 每批都要有测试,放在 Prism 现成的 `modules/*/tests/` 位置;
2. 不破坏任何现有单请求路径 —— 小文件上传、原有项目列表、原有对话行为,改动前后必须一致;
3. 改动集中,便于以后跟上游合并时识别;
4. **每批上线后在《新服务器部署说明.md》的"已包含的自定义改动"表里登记一行** —— 现在那张表只有"上传分片化"一条,再加四项不登记,半年后没人说得清哪些是自己改的。
