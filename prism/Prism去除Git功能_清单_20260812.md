# Prism 去除 Git 功能 · 可删/不可删清单

> 2026-08-12。目标:界面与接口层面彻底不出现 git;安装方式固定为 npm(tar 包部署)。

## ★ 最终决定(2026-08-12 确认,以本节为准)

| 项 | 决定 |
|---|---|
| **检查点(Checkpoints)** | **完全不动** —— 代码、开关、前端入口全部保留。它在非 git 仓库的项目里本来就空转(`claude-sdk.js` 有 `isGitRepository` 前置闸,全文无 `git init`),不影响任何东西;将来若某个项目建了仓库,它自动开始工作 |
| **installMode** | **固定 `'npm'`**,不再支持 git 安装。后续所有环境统一 tar 包部署 |
| **其余全部 git 功能** | **全部移除**(见第一节"可删,不影响任何功能"+ 第二节的项目克隆) |
| `plugin-loader.js` 读 `.git/config` | **保留**(只读文件、不调 git 命令,零成本;删了插件列表显示不出来源) |
| `users.git_name / git_email` 两列、`github_tokens` 表 | **只停止读写,不删列**(SQLite 老版本不支持 DROP COLUMN,删列要重建表) |

> 上一版把检查点列为"不可删"是基于"它是安全网"的判断;后来查证 `claude-sdk.js:1967` 的
> `if (await isGitRepository(options.cwd))` 前置闸,确认非仓库项目下它从不执行 —— 该判断已作废,
> 现按"保留但无影响"处理。

## 〇、先做:固定 npm 安装模式

`server/index.js:75` 现在是自动检测:

```js
const installMode = fs.existsSync(path.join(APP_ROOT, '.git')) ? 'git' : 'npm';
```

改为固定 `'npm'`。连带处理三处:

- `server/modules/system/system.routes.ts:103` 有 `if (!isPlatform && installMode !== 'git')` —— 某个自更新动作只在 git 模式下放行。固定 npm 后该分支永远走拒绝,直接把这个动作和它的路由摘掉,别留一个永远返回失败的接口。
- 前端 `src/components/version-upgrade/upgrade-instruction.ts` 按安装方式给不同升级指引,固定成 npm 文案(解包 + `npm ci && npm run build`),`upgrade-instruction.test.ts` 同步改。
- `src/components/sidebar/view/Sidebar.tsx` / `SidebarModals.tsx` 透传的 `installMode` 可以留着(值恒为 npm),也可以一并简化;留着改动更小。

**注意**:老服务器 `~/prism` 目前**是 git 安装的**(有 `.git`,只是属主不对导致 `git log` 报 dubious ownership)。固定成 npm 后,那台也不能再用 `git pull` 升级,必须改走 tar 包。两台机的部署方式要统一,否则代码会分叉。

## 一、可删,不影响任何功能

删掉之后唯一的变化是"没有 git 功能了",不牵连别处。

### 后端

| `server/routes/git-args.js` | 6 KB | 命令参数校验 |
| `server/utils/gitConfig.js` | 1 KB | 读写 user.name/email |

- `users` 表:`git_name`、`git_email` 两列

## 二、可删,但有代价

| 项 | 代价 | 建议 |
|---|---|---|
| **项目克隆** `modules/projects/services/project-clone.service.ts` | 新建项目只能指向本地已有目录,不能从 GitHub 地址克隆 | **删**。你们的项目都是本地目录,顺带把新建向导里那条路径摘掉,否则点了会报错 |
| **插件来源识别** `utils/plugin-loader.js:195-198` | 它读插件目录下的 `.git/config` 判断插件装自哪个仓库;删了插件照常可用,只是列表显示不出来源 | **保留**。这段只是读文件,不依赖 git 命令,留着零成本 |

## 三、不可删

### ① 检查点(Checkpoints)—— 建议保留

`server/services/git-checkpoint.js`(35 KB)+ `server/routes/checkpoints.js`。

它虽然用 git 实现,但**功能上不是版本控制,是安全网**:`claude-sdk.js` 第 29 行 import 它,第 1959 行起在**每一轮非斜杠对话的前后打快照**(源码注释:"Git checkpoints wrap every non-slash chat turn when the project is a repo"),agent 改坏文件可以事务性回滚。`checkpoints.js` 又反过来依赖 `claude-sdk` 与 `chat-run-registry`,三者环状咬合。

**删它等于动对话主链路**:必须同步改 `claude-sdk.js` 的每轮流程,否则 import 直接断、聊天全挂。而且用户在 UI 上看到的是"检查点/回滚",不出现 git 字样,不构成"界面里有 git"的困扰。

**结论:保留。** 这样本次移除完全不碰 `claude-sdk.js`,风险大幅下降。

### ② `installMode` 那一行本身

不能删,只能固定成 `'npm'`(见第〇节)。它判断的是 Prism 自己怎么装的,与"给用户用的 git 功能"无关。

## 四、改动规模与顺序

后端删 5 个文件 + 改 3 处引用;前端删 1 个目录 + 9 个文件 + 改 3 处注册;DB 只停用不删列。合计约 **半天**,不含验证。

建议顺序:先**后端摘挂载**(`/api/git` 不再存在)→ 跑一次确认聊天、文件、检查点都正常 → 再删前端入口和文件 → 最后固定 installMode 并统一升级文案。

验证要点:① 聊天正常且**检查点仍在工作**(发一轮消息,看 events 里有没有 `checkpoint_created`);② 新建项目(本地目录)正常;③ 设置页、首次引导、命令面板都不再出现 git 项且不报错;④ `/api/git/*` 返回 404;⑤ 侧边栏版本提示是 npm 文案。
