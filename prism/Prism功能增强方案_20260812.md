# Prism 功能增强方案(对标 CloudInk)

> 2026-08-12。范围:静态网页发布、HTML/Markdown 双模预览、多用户隔离、会话收藏。
> 已排除(用户明确不做):四种执行模式挡位、单消息 10 附件 / 500MB、粘贴截图直传。

## 先说一个查证结论:多用户这件事比预想的重

翻了 `server/modules/database/schema.ts`:

- `projects` 表字段是 `project_id / project_path / custom_project_name / isStarred / isArchived` —— **没有 owner**
- `sessions` 表字段是 `session_id / provider / provider_session_id / custom_name / project_path / jsonl_path / isArchived / ...` —— **没有 user_id**
- `users` 表存在(密码、token_version、is_active),但项目和会话不归属任何用户

也就是说 **Prism 目前是"单租户多账号"**:谁登录进来看到的都是同一套项目和会话。而 CloudInk 的 `sessions` 有 `user_id` 外键到 `users`,`messages` 外键到 `sessions`,README 里写明"所有会话与消息查询都会同时校验当前用户"。

结论:**你们用项目名当用户名(alice_zhu / huping / liwei…)不是偷懒,是当前架构下唯一可行的绕法。** 真要做隔离是架构改动,不是加个字段,详见方案 C。

## A. 静态网页发布(建议优先做,约 1 天)

### 现状与差距

Prism 现在的发布是**定制链路**:`ma_pipeline` 的 `publish_html` 把文件拷到 `PUBLIC_DIR`,用 `URL_BASE` 拼出地址。只服务营销诊断报告这一个场景,agent 产出的其它 HTML 没法一键分享。

CloudInk 的做法是通用能力,而且实现很轻:一张表 + 一个公开路由。

### 方案

**数据结构**(新增一张表,走 `modules/database/migrations.ts`):

```sql
CREATE TABLE IF NOT EXISTS published_pages (
  id           TEXT PRIMARY KEY,
  token        TEXT UNIQUE NOT NULL,      -- crypto.randomBytes(16).hex
  project_id   TEXT NOT NULL,
  rel_path     TEXT NOT NULL,             -- 相对项目根;file 时指向 .html,folder 时指向目录
  kind         TEXT NOT NULL DEFAULT 'file',   -- file | folder
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(project_id, rel_path)
);
```

**只存路径,不拷文件** —— 公开页面每次读工作区的最新内容。这一点直接抄 CloudInk,好处是"改完文件刷新就生效",不用重新发布。

**接口**:

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/projects/:projectId/publications` | 列出本项目已发布条目 |
| POST | `/api/projects/:projectId/publish` | 入参 `{ relPath, kind }`,返回 `{ token, url }` |
| DELETE | `/api/projects/:projectId/publish/:id` | 取消发布(删行 = token 立即失效) |
| GET | `/p/:token/*` | **公开路由**,无需登录 |

**公开路由怎么挂才不留洞** —— Prism 已有现成先例:`index.js` 里 `createSystemPublicRouter`(`/health`、`/api/ready`)是挂在 `/api` 那道 API-key 闸门**之前**的。新增的 `createPublishPublicRouter` 用同样位置挂载,并且:

1. 路径前缀用 `/p/`,与 `/api/*` 完全分开,避免以后有人给 `/api` 加中间件时把它连坐;
2. 只允许读**该条发布记录 rel_path 子树内**的文件,一律走现有的 `validatePathInProject`(Prism 这套是词法包含 + realpath 包含双重校验,比 CloudInk 只 realpath 父目录更严,直接复用);
3. MIME 走白名单(html/css/js/图片/字体/json),其余一律 `application/octet-stream` + `Content-Disposition: attachment`;
4. 响应头带 `X-Content-Type-Options: nosniff`,并给一条克制的 CSP;
5. 公开路由**不挂** `apiRateLimiter` 是不行的——必须挂,否则等于开了个不限流的口子。

**文件夹整站**:`kind='folder'` 时,`/p/:token/` 读目录下的 `index.html`,`/p/:token/assets/x.css` 读子文件。**缺尾斜杠要 301 到带斜杠的规范地址**(否则相对资源解析全错)——CloudInk 踩过这个坑,照抄它的处理。

**落点**:

```
server/modules/publish/
  publish.routes.ts              项目内的三个接口(走 authenticateToken)
  publish-public.routes.ts       /p/:token/*(无鉴权,挂在闸门前)
  services/publish.service.ts    token 生成、路径解析、MIME
  tests/
server/modules/database/
  migrations.ts                  加表
  repositories/published-pages.ts
src/components/file-tree/view/FileContextMenu.tsx   右键加"发布 / 取消发布 / 复制链接"
src/components/…/PublicationsPanel.tsx              发布列表(可放 Files 面板顶部)
```

**与现有 `PUBLIC_DIR` 链路的关系**:两条并存,不合并。`publish_html` 那条是**快照式**(拷贝到发布目录,内容冻结),适合"这一单的诊断报告";新的这条是**活链接**(引用工作区文件),适合 agent 随手产出的页面。合并会让报告的可追溯性变差——同一个链接下次打开内容变了,不是好事。

### 顺带解决的问题

你们那个"报告 HTML 转外链嵌入后,点目标人群跳到服务器页面"的问题,根因是宿主页的 base URL 污染了 `#锚点`。发布能力统一后,可以在公开路由返回的 HTML 里注入 `<base href="/p/:token/">`,锚点解析就锁死在自己的地址上了——这是顺手能带的收益,不用改报告生成端。

## B. 会话收藏置顶(顺带做,约半天)

`sessions` 表有 `isArchived` 没有收藏;`projects` 倒是有 `isStarred`。加一列即可:

```sql
ALTER TABLE sessions ADD COLUMN isFavorite BOOLEAN DEFAULT 0;
```

改动面:`repositories/sessions.db.ts` 加读写、列表查询按 `isFavorite DESC, updated_at DESC` 排序、侧边栏会话项加星标按钮。与项目星标共用同一套交互语义,不新增概念。

## C. HTML / Markdown 双模编辑与预览(约 1–1.5 天)

### 现状与差距

Prism 有 CodeMirror 编辑器和 `ImageViewer`,聊天区已经在用 `Markdown.tsx`(react-markdown + remark-gfm + rehype-highlight)。缺的是**编辑器标签里的预览模式**,以及 HTML 的沙箱预览。

### 方案

**Markdown 部分很便宜**:编辑器标签加"预览 / 源码"切换,预览直接复用聊天区那个 `Markdown.tsx`,零新依赖。

**HTML 部分的难点是相对资源。** 预览一个引用了 `./style.css`、`./img/a.png` 的页面,iframe 里发出的请求带不上 Authorization 头(和你们 WebSocket 那个 `?token=` 问题同源)。三个可选解法:

1. **一次性 token 的资源路由**(推荐):预览时后端签发一个短时效(如 5 分钟)、限定项目与目录子树的 token,iframe 用 `srcdoc` 注入 `<base href="/api/preview/:token/">`,相对资源自然走到这个路由。token 过期即失效,不落库(签在 JWT 里)。
2. 把资源全部内联成 blob URL —— 对大页面不现实,放弃。
3. 复用发布机制(方案 A)做临时发布 —— 会在发布列表里留垃圾条目,不干净。

选 1。它和方案 A 的公开路由是**两套 token**:发布是长期、可撤销、存库;预览是短期、无状态、不存库。别为了省事合并——合并意味着预览一次就产生一条可长期访问的记录。

**落点**:`server/modules/files/preview.routes.ts`(签 token + 资源路由)、`src/components/code-editor/` 加预览切换与 iframe 容器。

**沙箱**:`<iframe sandbox="allow-scripts">`,**不要**加 `allow-same-origin`(两者同时给等于没有沙箱)。

## D. 多用户隔离(先做档一,档二不建议在现有架构下硬做)

### 档一:归属标记 + 注册审批(1–2 天,防误操作)

**注册审批**(直接抄 CloudInk,很便宜):`users` 表加三列

```sql
ALTER TABLE users ADD COLUMN approval_status TEXT NOT NULL DEFAULT 'approved';  -- pending|approved|rejected
ALTER TABLE users ADD COLUMN approved_at DATETIME;
ALTER TABLE users ADD COLUMN reviewed_by INTEGER;
```

存量用户默认 `approved`(不能把现有人锁在门外);新注册进 `pending`,登录时在 `middleware/auth.js` 拦掉并给明确提示;管理员在设置页看待审列表,通过/拒绝都留痕。

**项目归属**:`projects` 加 `owner_user_id INTEGER`(可空 = 公共项目)。列表接口默认只返回"自己的 + 公共的",加一个"显示全部"开关。**这一档不改各接口的鉴权** —— 知道路径的人照样能访问,它解决的是"界面清爽 + 防误点",不是防越权。要如实写在文档里,别让人误以为已经隔离了。

### 档二:真隔离(不建议现在做)

要做到"A 无法访问 B 的项目",得给**所有**涉及 `project_path` / `session_id` 的接口加归属校验:files、git、checkpoints、agent、taskmaster、providers、websocket……面很宽。

但真正的拦路虎是 **Shell 面板**:它给的是一个真终端,开出来 `cd /home/jovyan/xxx` 就到别人目录了,应用层鉴权对它无效。除非同时做到:关掉 Shell、或每人独立容器/用户 + 文件系统权限。

CloudInk 的 README 对同一件事说得很清楚:"当前多用户能力提供的是**应用层的数据和目录隔离,不是操作系统级沙箱**,Bash 工具理论上可以访问运行服务账号有权限读取的其他路径"。它也没解决,只是把边界写明白了。

**所以档二的正确形态不是"改 Prism",而是"每人一个容器 + 各自一份 Prism"。** 在那之前,档一 + 把边界写进文档,是性价比最高的位置。

## 建议顺序与工作量

| 顺序 | 内容 | 工作量 | 理由 |
|---|---|---|---|
| 1 | A 静态网页发布 | ~1 天 | 收益最直接,顺带能治报告外链的锚点问题 |
| 2 | B 会话收藏 | ~0.5 天 | 一列 + 排序,做 A 的时候顺手 |
| 3 | C 双模预览 | ~1–1.5 天 | 提升"生成页面→看效果→调"的循环 |
| 4 | D 档一 归属 + 审批 | ~1–2 天 | 先把边界立起来,同时把"这不是真隔离"写进文档 |

A、B、C 三项互不依赖,可以拆开分批上;D 建议在前三项稳定后再动,因为它会碰 users/projects 两张表和登录链路。

## 统一的验收要求

每一项都要:① 有测试(Prism 已有 `modules/*/tests/` 的位置);② 不破坏现有单请求路径;③ 改动集中,便于以后跟上游合并时识别;④ 在 `新服务器部署说明.md` 的"已包含的自定义改动"表里登记一行。

第 ④ 条尤其重要 —— 你们这份 Prism 已经有上传分片这一项自定义改动了,再加四项而不登记,半年后没人说得清哪些是自己的东西。
