# 私域平台诊断流程(标准)

> 本文档为**固定标准流程**。对任一私域活动跑营销诊断→人群抽取→报告,照此执行。
> 入口:自动阶段 `run_one_activity.py <活动id>` → Agent 润色 → 收尾 `finalize_one_activity.py <活动id>`。
> 全链路里只有"润色"一步需要 Agent/人工,其余全部脚本化。

## 涉及表与 skill

## 产出表分区结构(重要)

两张产出表的写入方式由 driver **自动探测分区结构**后选择:

- **(dt, task_id) 二级分区(推荐)**:直接 `INSERT OVERWRITE` 本活动分区。天然幂等、无并发问题、不自读自写(表换 orc/parquet 也安全)。
- **(dt) 单级分区(现状,方案1)**:`OVERWRITE` 整分区时读回同分区其他 task_id 行再 UNION 写入。
  - ⚠️ **同分区多活动禁止并发跑**:读-改-写有竞态,并发会互相丢数据。
  - ⚠️ 依赖表为 **text 格式**:orc/parquet 下 Spark 禁止自读自写(`Cannot overwrite a path that is also being read from`),换存储格式前必须先迁二级分区。

### 二级分区迁移 DDL(一次性,建议尽快执行)

```sql
-- 人群表
CREATE TABLE tmp_dm.tmp_ctj_sy_crowd_test_v2 (
  mapid string, unionid string, is_pull string
) PARTITIONED BY (dt string, task_id int) STORED AS TEXTFILE;

SET hive.exec.dynamic.partition.mode=nonstrict;
INSERT OVERWRITE TABLE tmp_dm.tmp_ctj_sy_crowd_test_v2 PARTITION(dt, task_id)
SELECT mapid, unionid, is_pull, dt, task_id FROM tmp_dm.tmp_ctj_sy_crowd_test;

-- 报告表
CREATE TABLE tmp_dm.tmp_ctj_sy_report_v2 (
  url string, org_json string
) PARTITIONED BY (dt string, task_id int) STORED AS TEXTFILE;

INSERT OVERWRITE TABLE tmp_dm.tmp_ctj_sy_report_v2 PARTITION(dt, task_id)
SELECT url, org_json, dt, task_id FROM tmp_dm.tmp_ctj_sy_report;

-- 行数校验通过后 RENAME 切换(或改 driver --crowd-table/--report-table 指向 v2)
```

迁移后无需改 driver:分区探测自动走二级分区写法。

## 自动阶段(run_one_activity.py,约 8-10 分钟)

### Step 1/7 — 拉取活动特征数据
```
hdfs_get --table tmp_dm.tmp_ctj_mktv2_feature_day_v2_sy --where "task_id='<aid>'" --output <rundir>/data.parquet
```
SparkSession `SELECT...WHERE` 直接写出,**只取该活动行**,绕过整分区下载。产 parquet 目录(`pd.read_parquet` 可读)。
⚠️ 特征表按 `date` 分区,只传 `--where` 会全分区扫描;**已知活动日期时给 driver 传 `--pull-partition date=YYYYMMDD`**(透传 `hdfs_get --partition`)裁剪扫描量。

### Step 2/7 — prepare
```
cli.py prepare --data data.parquet --meta '{"campaign_type":"社群进群"}' --auto-meta --out <rundir>
```
`--auto-meta` 自动推断 campaign_name / target_products / 渠道 / 日期。内部:数据回填 → data_overview → **模型分析(lightgbm,目标=is_paid,抽 10 条候选决策规则 + top20 特征,AUC)** → 6 维度分析(漏斗/归因/人群/价格/平台/路径)→ 案例抽取。产 `state_partial.json`。
**driver 会在 prepare 后打印 auto-meta 推断摘要**——⚠️ 必须复核 `target_products`(`activity_product_name` 有时是页面名而非品类名,错了 Rule 11 跨品类推送错配等全部误判);不对就 `--meta` 显式传入后重跑。

### Step 3/7 — compute-thresholds
按 is_paid 成单率算每特征 CVR 最优切分点 → `adaptive_thresholds`;评估诊断规则集(以 `feature_schema/diagnostic_rules.yaml` 为准,当前 33 条;触发率/CVR差/显著性/`_signal_type`)。更新 state_partial + `thresholds_report.md`。

### Step 4/7 — draft
从 effective 信号自动装配报告骨架:findings / **audience_segments(模型高潜seg+规则seg,带 `direction`)** / narratives.problems / action_plan。产 `state_draft.json`(含 ~47 处 `[待润色]` 待润色)。

### Step 5/7 — 构建 crowd_rules.json(关键产物)
`cli.py crowd-rules --state state_draft.json --out <rundir>`(内部即 `crowd_translator.build_crowd_rules`,driver 不再直接 import skill 内部模块)汇总:
- 诊断规则(effective_signal=True)→ 按 `_signal_type` 定方向(positive→push,causal/leakage→exclude;leakage 因 effective_signal=False 实际不进人群)
- audience_segments → 用 segment 自带 `direction`(枚举 push/exclude,未知值告警并归 exclude)

每条带 `source` / `direction` / `pandas_filter` / **`sql_filter`(已翻译 Spark SQL:.notna()→IS NOT NULL、!=→<>、&→AND;字面量内运算符不误改)** / `estimated_size`。**直接从 state_draft 构建,不需要 polish/render**。
阈值语义化:新版模型树解析在**源头**就消掉科学计数法(哨兵 1e-35 → `<=0`/`>0`,其余阈值位置计数如 `0.00003`);展示层取整按 feature_registry 字段类型判断(count/ordinal/binary 才取整,rate 保留小数),`sql_filter` 始终用原始树阈值,展示与执行不脱节。翻译器对老 state 的哨兵文本仍有兜底归一化(仅指数≥20,不误伤真实小阈值)。

### Step 6/7 — 人群校验+抽取 + 写 crowd_test
- **人群只从 audience_segment 产出,不用 diagnostic_rule**
- **按 `finding_id` 分模型/规则(不按 direction)**:`fnd_model_*` = 模型输出(model_interpreter/lightgbm);`fnd_rN` + `fnd_pos_*` = 规则产出(diagnostic_rules agent,fnd_pos 是正向阈值 finding)
- **push = 模型输出 seg**(`--push-source model` 默认);**exclude = 规则 + 模型 seg 一起**(`--exclude-source both` 默认)。push 优先去重叠:模型 seg 用户归 push
- `--push-source {model,rule,both}` / `--exclude-source {model,rule,both}` 可切换
- **每条 `sql_filter` 在人群表上做 `LIMIT 0` dry-run 校验**:缺列/语法错误一次拿到,单条失败只跳过该条(不会拖垮整个 OR 大谓词查询)
- **每条规则记录人群表实际命中数 `population_size`**(一趟 `SUM(CASE WHEN)` 聚合;`estimated_size` 是特征表口径,评估规模以 population_size 为准)
- Spark:push 人群(去重 mapid)、exclude 人群(push 优先去重叠:excl `left_anti` join push)
- **幂等写入**:按分区结构自适应(见"产出表分区结构"节)
- `task_id = 活动id`(默认),`is_pull='1'`(推送)/ `'0'`(排除)
- 只写命中 push 或 exclude 的用户,**两类都没命中的中性用户不写表**

### Step 7/7 — 写 report 表 org_json
- 写入 `tmp_dm.tmp_ctj_sy_report.org_json` = **rules 数组**(无 wrapper 元信息),每条加 `crowd` 标签(`push`/`exclude`)标明该规则用在哪边
- **口径与 crowd_test 严格一致**:只含通过 Step 6 dry-run 校验、实际参与写入的规则(校验被跳过的规则不进 org_json,跳过原因记 `crowd_summary.json`)
- 每条 rule 字段:`source`/`name`/`direction`/`finding_id`/`pandas_filter`/`sql_filter`/`estimated_size`/**`population_size`**/`baseline_cvr`/`expected_cvr_mid`/`crowd`
- 模型 seg 同时出现在 push 和 exclude 两条里(反映"排除=规则+模型")
- `url` 留空(保留现值),待 finalize 阶段补;幂等写法同上节,driver 阶段就入库,**不依赖 polish/render**
- 与 `crowd_rules.json`(全量 effective 规则,审计用)区别:org_json 只存本轮实际圈人用的规则(audience_segment,带 crowd 标签)
- 汇总数字(push/excl/重叠/被跳过规则)另落 `runs/<aid>/crowd_summary.json`

## 报告阶段(润色 = Agent;其余自动)

1. **润色(Agent/人工,唯一非自动步骤)**:`state_draft.json` → `state_full.json`:填 ~47 处 `[待润色]`(findings.detail / problems 的 title/narrative/impact/typical_case.profile_text/root_cause / actions 的 title/description/expected_impact)、删 `_draft`(置 false)、`_stage="full"`、headline≤60 字。方法见 marketing-audit `SKILL.md` 第 6 步与 `methodology/03..08`(历史参考:`runs/562499/polish.py`)。
2. **收尾(全自动)**:
   ```
   python3 finalize_one_activity.py <aid> --dt <与自动阶段相同的dt>
   ```
   依次:校验 state_full(_stage=full、无 [待润色],未完成拒跑)→ `run-tools self_critique`(`--skip-critique` 可跳过)→ `render`(产 diagnosis_report.{json,md,html} + crowd_rules.json;render 校验前自动截断 headline 到 60 字)→ 拷 HTML 到 `/home/jovyan/prism/public/diagnosis-report-<aid>.html`(公开地址 `https://friday_deployment_14540_algo_agent.gw.friday.17usoft.com/<name>.html`;`/html-files/` 路径已坏不用)→ **幂等补 report 表 `url`(保留 org_json)** → URL 落 `runs/<aid>/report_url.txt`。
   - ⚠️ `--dt` 必须与自动阶段一致,否则补不到原行(脚本发现无现有行会告警)
   - ⚠️ `prism/public` 随 pod 重建会丢,重要报告加 `--hdfs-backup-dir /ns-dcbi/dm/tmp/ctj/reports` 备份 HTML 到 HDFS

## 模型高潜人群抽选逻辑(skill 内置)

- 目标 `is_paid`;lightgbm 默认;遍历树叶节点,留 `count>=30`;每叶回溯路径成 AND 规则。
- `predicted_cvr=sigmoid(叶value)`,`lift=predicted_cvr/overall_cvr`。
- **筛高潜硬阈值**(`model_interpreter.py:40-41`):`lift>=2.0` 且 `覆盖>=100`。即预测成单率≥2×基线 且覆盖≥100人。
- 低基线活动(如 9元盲盒 0.71%)高潜叶子极窄→推送人群小(高精度);高基线活动(如 3.45%)推送人群大。属自然结果。

## 关键配置/默认

| 项 | 默认 | 可调 |
|---|---|---|
| 推送人群来源 | `model`(只模型输出seg) | `--push-source {model,rule,both}` |
| 排除人群来源 | `both`(规则+模型seg) | `--exclude-source {model,rule,both}` |
| 特征表过滤列 | `task_id`(新版) | `--filter-col activity_id`(旧版) |
| 拉取分区裁剪 | 无(全分区扫) | `--pull-partition date=YYYYMMDD`(可重复) |
| task_id | = 活动 id | `--task-id` |
| dt(产出分区) | 当天 | `--dt`(finalize 必须与自动阶段一致) |
| 模型高潜阈值 | lift≥2.0 且 覆盖≥100 | 改 `model_interpreter.py:40-41` |
| 写表方式 | 分区结构自动探测(二级=覆盖本活动分区;单级=方案1) | 迁移 DDL 见上 |
| skip 拉取 | 否 | `--skip-pull`(data.parquet 已存在) |
| HTML 发布目录/域名 | prism/public + friday 网关 | finalize `--public-dir` / `--url-base` |

## 每活动产出物

`runs/<aid>/`:`data.parquet` / `state_partial.json` / `state_draft.json` / `state_full.json`(润色后) / `thresholds_report.md` / `crowd_rules.json` / `crowd_summary.json` / `diagnosis_report.{json,md,html}` / `report_url.txt` / `run.log`(driver+子进程输出;本进程 Spark 的 JVM 日志只在终端)

`tmp_dm.tmp_ctj_sy_crowd_test`:`task_id=<aid>` 的 push/exclude 人群行
`tmp_dm.tmp_ctj_sy_report`:`task_id=<aid>` + 报告 URL + `org_json`(实际圈人规则,含 population_size)
