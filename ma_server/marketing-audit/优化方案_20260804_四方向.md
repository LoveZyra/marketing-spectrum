## 方向一:Phase 1.1/1.2 圈人包导出 + 场景草稿(ROADMAP P0 并行,"可立即做")

**目标**:补掉"诊断完即结束"的开环——产出先知/私域能直接用的圈人包和场景草稿,消掉核心痛点#1(人工拼接重)。

**现状依据(实读)**:`crowd_translator.py` 已是现成的 pandas→SQL 翻译器,render 时已产 crowd_rules.json("一等公民人群规则产物"——注释原话);`draft_builder.py` 已产 `action_plan.priority_actions`;cli.py 子命令注册模式成熟(现有 7 个子命令可照抄)。**这个方向 60% 的地基已经存在。**

**改动清单**:

1. 新增 `snippets/segment_exporter.py`:
   - `先知` 格式 → `segments_先知.json`:segment 名 / direction / 标签表达式(SQL,直接复用 crowd_translator)/ 估计人数;带 `--data data.parquet` 时附 mapid 明细文件;
   - `私域` 格式 → `segments_私域.csv`(mapid, unionid, segment_name):必须 `--data`,按各段 pandas_filter 筛明细。
2. 新增 `snippets/scene_generator.py`:`priority_actions` → `scene_draft.json`(scene_name / audience_condition 引用 segment / channel 取自 finding 渠道字段 / time_window 默认可配 / linked_action_id)。
3. `cli.py` 加 `export-segments`、`generate-scenes` 两个子命令(各 ~10 行注册)。
4. `schemas/` 加 `segment_export.schema.json`、`scene_draft.schema.json`。
5. `methodology/03_synthesis.md` 补"场景草稿生成约束"段(ROADMAP 6.2 点名)。

**关键设计**:只读 state/data,不碰主链;私域明细可能百万行,写 csv.gz 分片 + 行数上限参数,不进 json;`direction=exclude` 段默认不导出(与 push_sql 同哲学,防"排除包"被误投,notes 写明)。

**风险**:低(纯增量)。**验证**:examples/output_example.json 做单测输入 + schema 校验 + 1011270 端到端导出与 size.push 对账。**量级**:~400 行 + 测试,一天。

## 方向二:Phase 2 四象限规则分层(ROADMAP 标注的 P0,价值最高)

**目标**:拉新/留存/召回活动不再被 31 条"转化口径"规则误诊(核心痛点#2)。

**依赖初验——好消息,原料齐**(feature_registry 实查):`pre_is_repurchase`(历史多次成单 0/1)、`pre_is_target_product_repurchase`、集团新老客(intotime vs 历史首单时间)、"查看待支付卡片"(遗单召回信号)、"查看待出行卡片"(老客复购信号)、`pre_create/complete_order_cnt`。**`is_new_paid` / `is_repaid` 可在 `data_fallback.ensure_required_fields` 里派生,不必等数仓加字段。**

**改动清单**(照 ROADMAP §5.1-5.6):

1. `diagnostic_rules.yaml` 每条规则加 `scene:` 维度(conversion/acquisition/retention/recall),存量 31 条默认 `conversion`;
2. `DiagnosticEngine` 按 `campaign_type` 路由过滤规则(engine 不硬编码规则——约束#3);
3. 新增拉新/留存/召回规则各 4-8 条(进 yaml);`threshold_computer` 双口径参数化已支持(约束#2 原文确认过);
4. `campaign_type` 从 meta 推断时强制向用户确认(约束#5,照 target_products 的现有范式);
5. 方法论文档新增场景分层章节。

**风险**:中——新规则的业务正确性需要你们确认一轮(误诊的反向风险);缺省策略要定(建议:无 campaign_type 时按 conversion 跑,行为与今天完全一致,零回退)。**验证**:每类场景造 fixtures 哨兵回归(照 regress_direction 模式);存量 31 条行为不变性断言。**量级**:2-3 天 + 一轮业务确认。

## 方向三:性能续杯(compute-thresholds 与 domain 瘦身,口径零变化)

**事实**:compute-thresholds 对 5.9M 行实测 17-30 分钟。热点在 `threshold_computer._choose_cut`:每字段取 9 个候选分位数,再对**每个候选 cut 做两次全列扫描**(`(s<c).sum()` / `(s>=c).sum()` + CVR gap),重复扫描是大头。另 `platform_behavior.py` 有 5 处 `apply(`、funnel/case_extractor 各 1 处。

**改动清单**:

1. `threshold_computer.py`:每字段一次 `sort` + `np.searchsorted` 做全部候选统计(排序 O(n log n) 一次,之后每 cut O(log n));预计 17-30min → **1-3min**,数值结果与现实现**逐位一致**(纯计算等价改写,报告口径零变化);
2. `platform_behavior.py` 的 5 处 apply 向量化(map/np.where);
3. `case_extractor.py` 抽代表案例加行数上限(抽样本来就不需要全量)。

**风险**:低——有"新旧实现同数据逐字段 diff 相等"这个硬验证兜底。**验证**:小数据双实现全等断言 + events elapsed 前后对比。**量级**:半天~一天。与将来的列裁剪收益叠乘。
